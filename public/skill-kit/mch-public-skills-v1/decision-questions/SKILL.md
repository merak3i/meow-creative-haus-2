# Questions that change the work

## Inputs

The request, existing decisions, constraints and available project evidence.

## Workflow

1. Read the available context before asking. Identify unknowns whose answers would materially alter the result.
2. Separate reversible implementation defaults from decisions only the user can make.
3. Ask the smallest useful set of focused questions. Include a recommended option and its tradeoff when choices are clear.
4. Continue independent work while a required answer is pending. Do not treat silence as authorization.
5. Record the resolved choices and proceed without repeatedly reopening them.

## Deliver

A brief set of necessary questions or a stated assumption followed by progress.

## Limits

Do not require clarification merely because several acceptable implementation choices exist. Follow the user's current request and the host application's permissions. This instruction file grants no tool access or extra authority.

## Example request

Review this brief. Ask only questions whose answers change the result; choose sensible defaults for reversible details.
