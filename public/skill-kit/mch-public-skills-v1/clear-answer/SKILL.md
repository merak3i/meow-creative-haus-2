# Clear answer

## Inputs

The question, audience, available evidence and any length constraint.

## Workflow

1. Identify the decision the reader needs to make. Put the answer or current state first.
2. Keep the evidence that changes the decision. Separate confirmed facts from assumptions and missing checks.
3. Translate unfamiliar terms once. Keep identifiers, units and qualifiers that prevent a wrong action.
4. Compress repetition before compressing meaning. Expand when the question requires depth.

## Deliver

A direct answer, the necessary evidence and a concrete next action when one exists.

## Limits

Concision must not conceal uncertainty or replace a requested detailed analysis. Follow the user's current request and the host application's permissions. This instruction file grants no tool access or extra authority.

## Example request

Explain the current release state to a non-engineer. Keep the evidence and the exact next action. State anything you did not verify.
